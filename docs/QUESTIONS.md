# ユーザーへの確認事項・決定事項

## 決定済み(2026-07-08 回答反映)

### 1. iOS のビルド・配布方法 → **Apple Developer Program + TestFlight**
GitHub Actions(macOSランナー)でビルドし、TestFlight で配布する。
署名・アップロードの自動化(fastlane 等)は Phase 4 で整備する。

### 2. 認証方式 → **Cookie(WebViewログイン)のみ**
KLMS はアクセストークンを発行できるが**1時間で失効する**ため実用にならない
(原因追及はしない方針)。ユーザーに発行の手間を掛けさせない点でも
WebView ログイン+セッション Cookie 永続化が妥当。
設定画面のトークン入力 UI は撤去済み(AuthService のトークン対応コードは
将来のために残してあるが、UI からは使えない)。

### 3. アナウンス通知の即時性 → **サーバーレス(ローカル通知)で確定**
外部サーバーなしでの「即時」プッシュは技術的に不可能
(プッシュ通知は APNs/FCM に送信するサーバーが必須のため)。本アプリの方式:

- **締切リマインダー**: 事前スケジュール型なので両OSとも**正確な時刻に発火**
- **アナウンス通知**: バックグラウンド同期時に検知してローカル通知
  - Android: 15分〜の定期実行(設定で 15分/30分/1時間/3時間/オフ)→ 準リアルタイム
  - iOS: BGAppRefreshTask。実行間隔は OS が利用状況から決定(数十分〜数時間)

### 4. お問い合わせ先 → プレースホルダーのまま(後日決定)
`lib/core/constants.dart` の `contactUrl` を差し替えるだけで変更可能。

### 5. Safari 等の外部ブラウザとの Cookie 共有 → **不可能(OS制約)**
アプリ内 WebView の Cookie ストアはアプリごとにサンドボックス化されており、
Safari / Chrome へ持ち出すことはできない。ただしアプリ内ブラウザ
(課題・ファイル・コースページの閲覧はすべてこれ)では保存済みセッションが
常に効くため、アプリ内で完結する限り再ログインは不要。

## 採用した前提(異議があれば変更可)

- **時限のデフォルト**: 月〜金・6限、慶應の標準時間
  (1限 9:00–10:30 / 2限 10:45–12:15 / 3限 13:00–14:30 / 4限 14:45–16:15 /
   5限 16:30–18:00 / 6限 18:10–19:40)。設定で変更可。
- **「LMS上で完了」の判定**: 提出状態(submitted/graded)**または**
  Canvas Planner の「完了にする」マーク(planner override)。
  どちらかが立てばアプリでも完了扱い。
- **完了矛盾の通知**: 「アプリで手動完了 ∧ LMSでは未提出かつ完了マークなし」を
  同期時に検知したら、課題ごとに1回だけ通知(LMS側が完了になればリセット)。
- **アプリ→LMSへの完了書き込みはしない**: アプリ側の手動完了を Canvas Planner に
  書き戻すと「LMSでは未提出」という矛盾検知が機能しなくなるため、一方向のみ。
- **バックグラウンド同期のデフォルト**: 30分ごと(Android)。

## 追加提案(競合アプリ超えのために)

1. **課題詳細のオフラインキャッシュ**: 電波のない場所でも課題内容・締切を確認可能に
2. **時間割からコースページへのタップ遷移**(実装済み)
3. **「今日のダッシュボード」ウィジェット**: 今日の授業+今日締切の課題を1枚に
4. **提出忘れ防止の"最終警告"**: 締切1時間前になっても未提出(LMS基準)の場合の追い打ち通知
5. **成績(スコア)表示ページ**: Canvas の成績APIから取得(Phase 4)
6. **課題タイトルの正規表現フィルタ**(除外ワードの上位版・上級者向け)
